# 从 Duolingo 复刻实践改进 rebuild

本次 Duolingo 网页到 Swift 试验已经结束，尚未完成 1:1。它的价值是提供了真实探索、模具缺口、实现反馈与接续经验；下一步是把这些经验变成可复用 workflow，不要求再做消融来证明它值得使用。

用户保存的旧 Goal 同时要求文档、探索、模具、1:1、消融和教育基座。新的默认模板保留复刻目标和交付标准，把执行方法交给 workflow，把具体要求交给 E2E；消融退出默认完成条件。旧 Goal 是本次复盘输入，不是重新开始 Duolingo 的指令。

## 已观察的失败与改法

| 实践事实 | 对 rebuild 的改进 |
| --- | --- |
| 初次展示没有合格主页、UI不像、声音不足，而局部业务检查已通过 | 从第一批完整旅程共同验收前端与业务；产品实际差异决定工作优先级 |
| 课程／断言／版本持续增加，完整体验收敛不足 | 报告围绕用户需求和差异，Goal 不以检查数量推进 |
| API 的裁切角色图不能解释屏幕上的完整动画 | 将矛盾反馈用于改变探针，实际追查 Canvas／Rive 和资源消费者 |
| 当前视口漏掉头像分类、完整选项和页面下层内容 | 区分库存、可达、执行与验证，主动探索观察器尚未识别的入口 |
| DOM、焦点、截图、重载和可操作状态出现矛盾 | 保留失败，先修采集方法和状态身份，不挑有利读数 |
| 同一控件的 hover、click、Enter 不等价 | 探索与历史分别记录输入方式；一次执行不清除其它方式 |
| 反馈真实改变了下滚／月份键盘探针，发现进入模具与 Swift | RSI 直接服务下一步探索和模具扩充，无需新研究实验作为前提 |
| 几何和核心通过仍伴随整图失败；文件存在不等于实际声音 | 保留独立测量，交付按完整体验判定，并给差异可定位的诊断 |
| README、哲学、架构、研究和 Roadmap 累积批次进展 | 主文档恢复单一职责，当前入口由项目清单连接，历史退出主阅读路径 |
| 原生 Goal、Harness、Pipeline 各有状态与完成条件 | 原生 Goal 拥有持续执行；Stop Hook 已删除，兼容工具仅手动验证 |

## 本次落地范围

统一 workflow 现在使用原生 Goal；项目 CLI 准备 Goal 参数、读取当前入口和调用现有命令，保留失败退出码。Duolingo 的封存数据用于验证入口接线，不恢复原版探索或修改 Swift。新模板不包含默认消融要求，也不另写运行 Goal 文件。

工具检查能验证参数、状态读取和命令执行，不能替代下一个项目的完整实际复刻。后续成果见 [Roadmap](ROADMAP.md)。旧主文档和长批次记录的检索方式见 [历史索引](history/README.md)。
