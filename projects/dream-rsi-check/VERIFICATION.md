# Dream-RSI 主循环验证

日期：2026-10-12。范围是论文第 3 节算法、命令接线和当前 Codex 的反馈消费；没有重启 Duolingo，没有进行消融或复刻收益比较。

## 当前 Codex 实际开发策略

当前会话调用 `collect` 保存第一棵树，读取 `replay` 的轨迹后写 v1；查看失败反馈后写 v2。三个版本在同一冻结池上比较。发现命令与独立评价器是本案例的固定可执行夹具，策略开发者是当前 Codex；没有调用夹具的自动 reviser，也没有启动嵌套模型。

| 版本 | 依据与行为 | 第一世界回放分数 | 结果 |
| --- | --- | --- | --- |
| v0 | 原策略：交替开分支与继续最新叶 | 0.575 | 比较基线 |
| v1 | 继续当前最佳叶，同时开新分支 | 0.45 | 低预算下增加调用成本，被拒绝 |
| v2 | 保留低预算的低调用路径；高预算并行；可见检查全过时停止 | 0.5816666667 | 被选中 |

下一次 `collect --pool` 实际使用 v2；已选文件与新树记录的部署 SHA 同为 `13b3e98c95736d1ac177b2999feeacaee8320cea9afaf7fb4f8b613e96f0d023`。第二轮实际发出 `[root]`、`[best leaf, root]` 两个批次，保存两层独立快照，发现命令收到一份已完成世界上下文。

两棵树包含 5／4 个节点（含根），实际发生 7 次生成和 7 次独立程序评价。随后对全部两个世界做离线回放，分数 0.5816666667／0.4566666667，等权平均 0.5191666667；离线阶段生成、评价命令调用均为零。不同历史池上的分数不能直接解释成收益增长。

## 自动检查

`python3 -m unittest discover -v`，89 个检查通过。新增检查覆盖：

- 多层分支与根子节点创建顺序、不可继续的叶仍计算轮数、非法选择拒绝。
- 未揭露结果改变不影响先前决策输入，策略不能通过修改输入改变保存的历史。
- 论文式 (1) 手算值、零调用项、Pareto 支配、全部历史平均、原策略保留及失败修订。
- 真正并发的生成请求、父上下文继承、独立恢复和执行评价、胜出策略实际再次部署。
- 保存池接续、离线零发现／评价调用、历史新增文件／策略篡改和协议变化检测。
- 无正分数时保存 collected-pool，明确不可评分；当前 Codex 路径无需 developer 子进程。
- 导出的当前会话三个版本及两棵世界重新计算，复现保存的回放分数。

最初的运行检查暴露并修复了 macOS `/var` 与 `/private/var` 的路径解析问题。夹具 developer 的第一版也曾因增加调用而未胜出，已按反馈修正，未放宽评分。修改固定 worker 后，旧池被协议校验拒绝；随后使用独立新池，未混合评价协议。

## 范围

这证明主循环可以执行、比较、拒绝退化修订并部署选中策略，不证明任意 App 的遗漏都会自动被找到，也不证明模型发现 agent 的通用效果。真实 App 仍需案例观察器、真实原版状态恢复和业务／前端独立评价。论文九项基准、附录工程设置和平台安全隔离不是本记录的验证结论。
